# 聊天文字草稿刷新恢复

用户授权继续完善使用体验。本轮聚焦未发送／发送失败的聊天文字刷新恢复；沿用已有页面与公开 HTTP 测试边界，先测试后实现，最后复核、本地更新和提交，不推送合并。

## 这份计划替产品做的决定

- 草稿保存在当前浏览器标签页的 sessionStorage，刷新可恢复；不承诺关闭标签或跨设备恢复，不自动发送。
- 先通过真实会话确认当前终端用户和工作空间，再按身份、Agent、会话隔离草稿；没有有效身份时不显示本地草稿。
- 增加只读 GET /api/v1/end-user/me，仅返回当前 cookie 对应的 end_user_id、workspace_id；不接收用于指定其他身份的参数，不返回凭据，响应不缓存。
- 恢复文字、保留原请求重试标识；附件文件需重新选择，并给出明确提示。只有内容与原请求相同才复用发送标识。
- 成功发送、主动清空、从本机移除会话和清空本机记录应清理对应草稿；存储不可用时允许继续输入并提示不能跨刷新恢复。
- Agent 配置草稿沿用已完成的离页提醒，本轮不扩展它的保存机制。
