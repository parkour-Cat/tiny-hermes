# M1 Phase 4C Secret Envelope Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans or
> superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Deliver slice 4C of product closure: a Secret stored as ciphertext
under a wrapped DEK, never readable as plaintext over HTTP, unwrapable at model
call time, rewrappable when the KEK rotates, and manageable from the console.

**Architecture:** Envelope encryption. Each Secret has its own DEK. The DEK is
wrapped with the deployment KEK (`TINY_HERMES_KEK`). `credential_ref` on a
model endpoint may name a Secret id **or** still name an environment variable
(overlap). API Keys stay hashed; they are not Secrets.

**Tech Stack:** FastAPI, SQLAlchemy 2 async, `cryptography` AES-256-GCM,
React 19 / Ant Design 6 for the Secrets page.

**Authority:** `docs/superpowers/specs/2026-08-13-m1-product-closure-design.md`
§9 and §11. Product design v2.4 and technical design v1.1 win ties.
4B verification: `docs/superpowers/verification/2026-08-13-m1-console.md`.

## 2. Envelope

```text
plaintext  --AES-256-GCM(DEK, nonce)-->  ciphertext
DEK        --AES-256-GCM(KEK, wrap_nonce, aad=key_id)-->  wrapped_dek
```

KEK is 32 bytes, configured as standard base64 in `TINY_HERMES_KEK`.
`TINY_HERMES_KEK_ID` names the current wrapping key (default `v1`).
`TINY_HERMES_PREVIOUS_KEK` / `TINY_HERMES_PREVIOUS_KEK_ID` are the prior pair
for rewrap. A backup of `secrets` without the matching KEK cannot decrypt.

Mask is computed at create from the plaintext (first/last 2 characters, rest
bullets) and stored. It is not reversible.
