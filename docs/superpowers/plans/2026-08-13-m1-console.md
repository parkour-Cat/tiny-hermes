# M1 Phase 4B Console Product Closure Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans or
> superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Deliver slice 4B of product closure: the console a workspace developer
uses to bind tools, publish with a field-level diff, talk to a persistent
Session in Playground, inspect messages / tools / files on a Run, manage
members and API Keys, and register model endpoints — plus a locale switcher
and a persisted theme.

**Architecture:** Extend `apps/web`; do not replace it. Playground is a Runs
API client with a cookie, never a Chat Completions client. Backend gaps that
block the console (PATCH agent, version spec, members write, session messages,
artifacts-by-run) land in this slice so the UI does not invent a parallel
protocol. Secrets wait for 4C.

**Tech Stack:** FastAPI, SQLAlchemy 2 async, React 19, Ant Design 6, Vitest,
Playwright, existing Runs/SSE/`useRunEvents`.

**Authority:** `docs/superpowers/specs/2026-08-13-m1-product-closure-design.md`
§8 and §11. Product design v2.4 and technical design v1.1 §15 win ties.
4A verification: `docs/superpowers/verification/2026-08-13-m1-machine-identity.md`.

## 1. Working rules

- Branch from the 4A HEAD (`cursor/phase-4a-machine-identity-c232`), not from
  `main` and not by continuing commits on the 4A branch name.
- Observe a focused failing test before production code. Commit when it passes.
- Database integration tests target only `tiny_hermes_test`.
- Use `uv run --no-sync`; do not run `ruff format`.
- Default locale stays `zh-CN` so existing Playwright and component tests that
  assert Chinese labels keep working. `en-US` is covered by a dedicated test
  after the switcher exists.
- The console never client-filters security: the route parameter is
  `X-Workspace-Id`; 403/404 are shown as the platform returned them.
- Do not render Approvals, Usage, task trees, skills, Feishu, or a fake
  Secrets page.
- After every task, append a short note to
  `.superpowers/m1-implementation-learning-notes.md` (gitignored).

### Task 3: Members invite, role change, and remove

Invite is by **email of an existing User**. Unknown email is a named error,
not an implicit signup. No registration API is added.

```text
POST   /api/v1/workspaces/{id}/members     { email, role }
PATCH  /api/v1/workspaces/{id}/members/{user_id}  { role }
DELETE /api/v1/workspaces/{id}/members/{user_id}
```

Rules:

- Writes: `workspace_admin` or platform admin (audited). Viewer/developer: 403.
- `GET …/members` already exists; the response adds `subject` (the local
  identity email) so the invite UI can show who is there.
- Duplicate membership: 409 `member_already_present`.
- Removing or demoting the last `workspace_admin`: 409 `last_workspace_admin`.
- Role is one of `workspace_admin` / `developer` / `viewer`.

Look up the invitee through the local identity subject (same column login
uses). Seed a second user in integration tests the same way
`test_missing_membership_is_forbidden_before_resource_lookup` already does.

### Task 8: Playground

**Files:**
- Create: `apps/web/src/pages/PlaygroundPage.tsx` + test
- Modify: `App.tsx`, `AgentsPage.tsx` (link), `ConsoleLayout` if needed

Route: `/workspaces/:workspaceId/agents/:agentId/playground`.

Behaviour:

- Cookie + CSRF. Persistent Session for this Agent and this caller. Reuse the
  latest matching persistent Session if `GET /api/v1/sessions` returns one;
  otherwise `POST /api/v1/sessions`.
- Composer: `POST /api/v1/runs` with `input` and a fresh `Idempotency-Key` per
  send.
- Live: existing `useRunEvents` plus `GET …/sessions/{id}/messages` once the
  Run is terminal (and on load). Token SSE is not required.
- Buttons only from `available_actions`. When `queue.status ===
  session_blocked`, also offer `queue.available_actions` against the **head**
  Run id (`queue.blocked_by_run_id`). Sending while blocked still expects 201.
- Files: parse `artifact_id=` from tool-result text and list via
  `GET /runs/{id}/artifacts`; download uses `/api/v1/artifacts/{id}/content`.
  No `/workspace/data` editor.
- 「新 Session」creates an unrelated persistent Session and switches to it.

- [ ] **Step 1: Component tests** — send with Idempotency-Key; blocked queue
  renders head actions; new session POSTs `session_mode=persistent`

- [ ] **Step 2: Page + route**
