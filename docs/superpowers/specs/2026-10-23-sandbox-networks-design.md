# 每个沙箱一个网络

日期 2026-10-23。产品设计 v2.21 §1.21 第 4 条的实现设计。

## 1. 要解决什么

现在所有联网的沙箱接在同一个 `internal` 网桥（`sandbox-egress`）上。`internal` 去掉了出网，
没有去掉容器之间的互访：一个 Run 能连到同主机上另一个 Run 在沙箱里起的端口（运维手册 §10）。

## 2. 做法

- controller 为每个沙箱建一个 `internal` 网桥，名字由沙箱实例 id 决定：
  `tiny-hermes-sandbox-<instance_id>`。网桥上只有两样东西：这个沙箱，和出站代理。
- 出站代理容器在建网时被接上这个网桥，别名取自 `EGRESS_PROXY_URL` 的主机名（Compose 里是
  `egress-proxy`），沙箱里的代理变量不用改。
- 沙箱销毁时（`_remove`、`_discard`、`_evict`、清理遗留、主机巡检），容器删掉之后，先把代理
  从网桥上断开，再删网桥。
- 网桥带和容器一样的标签（Run、实例、工作空间），主机巡检按标签找出没有记录的网桥删掉。
  建网之后、写下记录之前失败，留下的网桥由巡检收走。

## 3. 地址从哪来

Docker 默认的地址池在一台机器上只能分出大约 31 个网络。之前讨论时说「几百个」是错的。所以
网段由 controller 自己分：

- 新配置 `SANDBOX_NETWORK_POOL`：一段专门给沙箱用的私有地址，比如 `10.240.0.0/16`。
- 每个沙箱从里面随机取一个 `/28`（14 个可用地址，用到 2 个：沙箱和代理）。`/16` 能分出 4096 个。
- 随机取到已经被占的网段时，Docker 拒绝（地址池重叠），换一个再试，最多 8 次。
- 不记账：Docker 自己知道哪些网段在用，再用一张表记同一件事，会出现两边对不上的情况。
- 部署要保证这段地址不和主机所在的网络、Compose 自己的网络冲突。

## 4. 配置

| 变量 | 作用 |
|---|---|
| `SANDBOX_NETWORK_POOL` | 沙箱网段的地址池。为空则沙箱不联网（和现在 `SANDBOX_EGRESS_NETWORK` 为空时一样） |
| `SANDBOX_EGRESS_PROXY_CONTAINER` | 出站代理容器的名字，controller 要把它接到每个沙箱网桥上。Compose 默认 `tiny-hermes-egress-proxy-1` |
| `EGRESS_PROXY_URL` | 不变 |

`SANDBOX_EGRESS_NETWORK` 和 Compose 里的 `sandbox-egress` 网络删掉。还设着旧变量、没设新变量的
部署，controller 启动时记一条警告，沙箱不联网：宁可明确地不联网，也不悄悄回到共享网桥。

## 5. 代价

- 冷启动多两次 Docker 调用（建网、接代理），删除也多两次。
- 出站代理接在很多网桥上。它的指标端口在每个沙箱网桥上都连得到，仍然靠 token 挡住
  （指标设计 §4.2）。
- 网桥的数量受 Linux 网卡数等限制。几千个以内不是问题，比单机能跑的沙箱数高得多。

## 6. 怎么验证

真实 Docker：

1. 两个沙箱各在自己的网桥上，A 连不到 B 起的端口（这是这一遍的目的）。
2. 每个沙箱连得到代理（用一个替身容器充当代理，接在网桥上监听）。
3. 沙箱仍然连不到公网。
4. 销毁后网桥不在了，代理不再接着它。
5. 巡检删掉没有记录的网桥。
6. 网段重叠时换一个再试（用替身 engine 的单元测试）。

另外：CI 的 compose-e2e 一直没开联网沙箱（没设 `SANDBOX_EGRESS_NETWORK`），这条路从来没在 CI
里走过。这一遍在 CI 里把 `SANDBOX_NETWORK_POOL` 打开。
