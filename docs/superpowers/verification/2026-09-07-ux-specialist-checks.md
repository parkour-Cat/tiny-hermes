# 键盘、角色权限与异常恢复专项验收

日期：2026-09-07。对应 [专项计划](../plans/2026-09-07-ux-specialist-checks.md) 与 [实施进度](../ux/2026-09-06-implementation-progress.md)。沿用用户授权，在独立本地环境检查、修复、回归并更新本地服务；不推送或合并。

## 已修复的问题

| 问题 | 现在的行为 | 证据 |
| --- | --- | --- |
| 聊天发送失败会提前清空输入 | 等待发送成功后再清空；失败保留文字和附件，发送中防止重复点击 | 先失败后修复的组件测试、真实浏览器断网重试 |
| 服务器收到消息但响应丢失，重试可能再次创建任务 | 同一页面、同一会话、同一内容的失败重试沿用请求标识；成功后清除 | 浏览器先把请求送到服务器再丢弃响应，重试并刷新，最终只有两次不同输入对应的两条用户消息和两条回复 |
| 自定义菜单打开后键盘焦点不进入菜单 | 打开定位到当前选项或首个可用项；方向键和 Home／End 导航，Esc 关闭并返回触发按钮 | Composer、AgentPicker、SessionItem、ChatPage 测试及浏览器实测 |
| 按钮和说明文字在部分主题中偏淡 | 加深浅色主题铜色、按主题配对聊天按钮文字，显式设置控制台辅助与说明文字颜色 | 深浅主题浏览器文字对比度断言均要求至少 4.5:1 |
| 附件无法读取时无提示 | 显示中英文错误说明，保留文字及附件，恢复发送状态，允许移除后重新选择 | File.text() 拒绝的测试实际失败后修复，完整聊天回归通过 |

测试提交先于实现。附件准备失败和网络请求失败分别处理：前者在输入框旁提示，后者使用页面已有错误提示。未改动已发布 AgentVersion、后台任务执行或数据库结构。

浅色按钮原对比度为 4.28047，说明文字为 3.28904。首次只调整 `colorTextSecondary` 后，浏览器再次检出说明文字不达标；核对组件库发现 Typography 实际使用 `colorTextDescription`，补齐后通过。没有把中间失败记录成通过。CUA 复看已加载的 Agent 列表，浅色说明文字实际为 `rgb(92, 83, 72)`，列表分隔和页面间距正常。

### 键盘、窄屏与保存恢复

在 320／390／768／1280px 检查待办和平台页面正文宽度、新建 Agent 弹窗边界及长名称输入。键盘打开菜单、方向键切换、Esc 关闭和焦点返回均有覆盖。

Agent 草稿保存请求故意断开后，页面显示错误并保留输入；恢复请求后可再次保存，刷新后读取已保存的新修订。聊天分别验证请求尚未送达和已送达但响应丢失的失败重试；成功发送后刷新能恢复会话。SessionItem 的移除确认取消及 Esc 焦点测试直接通过，不需要额外产品修改。

### 多角色

独立环境使用平台管理员和三个真实登录身份：空间管理员、开发者、只读成员。通过正常成员 API 分配角色，再以各身份的独立浏览器上下文验证页面按钮与实际请求。

| 身份 | 创建 Agent | 邀请成员按钮 | 平台管理入口／创建工作空间 API |
| --- | --- | --- | --- |
| 空间管理员 | 可用，API 201 | 可用 | 无入口，API 403 |
| 开发者 | 可用，API 201 | 禁用 | 无入口，API 403 |
| 只读成员 | 禁用，API 403 | 禁用 | 无入口，API 403 |

平台管理员完成创建工作空间、添加测试成员及常规管理流程。三种成员角色均实际执行，不能把未启用夹具时的跳过计入通过。

产品没有本地用户注册 API，因此只有测试身份初始化通过 ORM 完成；脚本要求显式 `TINY_HERMES_E2E_ROLE_FIXTURES=isolated-ux-only`，在 `tiny-hermes-ux-qa` 内运行，遇到已有身份不修改密码或角色。角色分配、登录和权限验收使用真实 HTTP／UI。此结果不等于所有接口、所有角色组合都已穷举。

### 服务恢复

只对独立栈 `tiny-hermes-ux-qa` 执行两类演练，使用平台自带确定性模型和临时 3000ms 延迟：

- 执行中重启 worker：11.69 秒后完成；8 条事件连续、2 次执行租约，最终事件为 goal_verdict。
- 停止 Redis：任务仍在 6.14 秒后完成；恢复 Redis 后连续 3 个任务均在约 6 秒完成。

演练后恢复 worker／Redis，并去除临时延迟再运行完整浏览器流程。没有停止原环境服务或删除数据卷。原始日志：`.superpowers/ux-service-recovery.log`。

## 这一遍没能证明什么

- 失败草稿和重试标识仅在当前页面内存中；本轮没有实现或证明未发送草稿跨刷新、关闭标签、跨设备恢复。刷新测试证明的是成功保存或发送后的恢复。
- 键盘覆盖常用菜单和弹窗；颜色辅助函数只处理普通纯色背景及透明背景叠加，不覆盖图片、渐变及所有透明度组合，也未做屏幕阅读器或系统输入法全量人工验收。
- 只执行 worker、Redis 两类重启演练，没有执行全部 scheduler、sandbox、配额或长时间压力演练。
- 本轮使用确定性模型、测试身份和测试企业凭据，没有重新调用真实模型，也没有真实飞书收发、企业 SSO 或实际外部嵌入网站验收。原账号会话已过期，未重置或猜测密码。
- 后台产品代码未修改，未重复运行上一轮后台全套测试；未取得当前提交的远端 CI compose-e2e 结果。

## 不声称什么

不声称全部 UX 永无缺陷、全部角色接口已穷举或达到完整无障碍认证；不把独立测试环境跑通等同于真实外部租户接入，不把失败重试保护说成跨刷新持久化；不声称已推送、合并或上线。合并前仍须取得当前提交的 CI compose-e2e 绿色结果。
