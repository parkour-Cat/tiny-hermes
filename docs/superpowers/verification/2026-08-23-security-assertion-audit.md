### 断言 4：补了执行层那一半

规划器拒绝有单元测试（`http_call_of` 对未绑定的名字抛 `tool_not_authorized`）。
它证明不了的是 **Worker 没有第二条通往实现的路**——规划器拒绝，只说明规划器拒绝。

补了一条集成测试：驱动一个真实 Run，模型对**注册文档上存在、但这个 Agent 没绑定**的
操作发出 `tool_call`，断言桩服务器**什么都没收到**。绕过规划器的路径会在这里显形，
而在这个仓库的其他任何地方都不会。

顺带钉住一件事：这种情况**不是** `waiting_approval`。请人批准一个 Agent 本来就无权
发起的调用，等于把一个不属于他的决定递给他。

## 2. 找到的三个缺口，都已修

三条的形状完全一样：**断言的前半句有，后半句没有**，而后半句恰好都是
**事后能不能查得出来**的那一半。

### 断言 2 — 终端用户越权：拒绝有，审计没有

原文「服务端**拒绝并写安全审计事件**」。拒绝自终端用户入口起就有测试；审计事件
**既无测试也无实现**——`ForbiddenRunAction` 映射到 `forbidden()`，后者
`audited=False`，一行不写。

差别在有人问「那个账号是不是在试探」的时候显出来：**一次不留痕的拒绝，和一个从未
发生过的请求无法区分**。平台能说「他没进来」，说不出「他试过」。

写在服务层而不是 HTTP 边界，因为只有那一层同时握着两个身份：谁伸的手、伸向谁的
会话。`forbidden()` 两个都没有。

### 断言 3 — 委派交集：零测试覆盖

`delegated_scope` 在**所有测试文件里出现 0 次**。集成套件里每一个子 Agent 都
「什么都不绑」（fixture 自己写了这一点），所以这个交集**只在它无事可做的那一格
被走过**。

补了单元测试，并用两种典型错误实现验证它们不是空过的。其中「**空即无限制**」——
最可能的那个错误写法——**会通过仓库里现有的每一条测试**，同时把父 Agent 的整个
工具箱交给每一个子 Agent。

### 断言 14 — 未批准目标：拒绝有，审计没有

同一个形状，但**原因不同，值得单独记**：这次审计行**写进去了又被回滚**，因为路由的
`except AgentCatalogError` 抢在依赖之前把异常转成了 `AppError`。

在那个 `AppError` 上设 `audited`（断言 2 的做法）**在这里来不及**：服务抛出 →
依赖的 `except` 先跑 → 路由**之后**才映射，那时事务已经没了。

而 `AuditedDenial` 这个机制**早就存在且从未被 raise 过**——`resources.py` 里四处
等着捕获它，全代码库没有一处抛。用多重继承接上：少了 `AuditedDenial` 那半，
记录被回滚；少了领域异常那半，调用方拿不到列出违规条目的 422。

## 3. 断言 7：先查清楚，然后它变小了

原文要求 Secret 在**提示词、日志、RunEvent、MemoryItem、SkillProposal** 上被拦截
或脱敏。初查的结论是「只有日志路径有测试，平台没有任何擦洗机制」，当时记为
**待决定：建拦截层还是证明结构性保证**。

**先查清楚是对的，因为查完之后这个问题小了一个量级。**

**结构性保证是真的。** Secret 只为一次调用解析、注入 `Authorization` 头，
从不进入模型上下文。这比擦洗强——擦洗要认出密钥，结构性不包含则根本没有东西可认。

**但它在一个地方破，而且只在那一个地方**：响应体。
`body = response.content` 直接成为模型读到的工具结果，所以一个**把收到的
`Authorization` 回显出来的对端**，就能把凭证送进模型上下文、RunEvent、以及一条
记忆提案够得着的地方。

**实测确认过**：造一个回显的桩服务器，密钥出现在会话正文里。

### 两处，不是一处

修好 HTTP 工具发送器之后去查 MCP 网关——**同一条路在那儿也存在**：同样注入
`Authorization`，同样直接 `return response.content`。测试证实它也漏。

**只修一处等于关半扇门。** 两处共用同一个 `credential_echo.without_credential`：
它们没有共同代码、注入同一个头、同样直接返回对端的字节——擦洗器住在其中一个里面
是半扇门，写两份就是有一份没人更新。

MCP 那条写成**独立测试**而不是并进 HTTP 那条，理由是：两条路不共享代码，
**修好一条不说明另一条**，而只看到一个测试的读者会合理地以为它管两边。

### 两个判断

**对端回显不是这个平台的过错，而且对端本来就有那个密钥**——没有任何东西泄露给
**它**。变的是密钥之后住在哪：**开发者可读（留痕）的会话正文、以及比 Run 活得更久
的记忆**。这些地方的访问规则和「出站层在一次调用期间持有」完全不同，
而悄悄把凭证从前者搬到后者正是这里要拦的。

**替换而不是拒绝。** 应答仍然是应答；一个因为 API 话多而失败的 Run，
比一个读到被涂掉字段的 Run 更糟。
