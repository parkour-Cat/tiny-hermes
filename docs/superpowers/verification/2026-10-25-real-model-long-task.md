# 真实模型长任务：用 bash + awk 写记账工具 `ledger`

日期 2026-10-25。本机 Compose 栈，模型是 DeepSeek `deepseek-chat`（OpenAI 兼容端点，上下文窗口 65536，单次最多输出 8192）。
worker 用的是 #161 的分支。

## 任务

让模型在沙箱里用 bash + awk（没有 Python，不联网）写一个记账命令行工具，并通过我给的测试脚本。任务描述里附上完整的
`tests.sh`，要求模型原样写下（给出 sha256），不准修改。跑完后我做三件事：

- 下载工作区文件，核对 `tests.sh` 的 sha256；
- 用**我自己那份**测试，在沙箱镜像里把它写的 `ledger` 跑 3 遍；
- 测试本身先用我写的参考实现验过：两版都全部通过；空实现分别只过 2/32 和 7/73。

| 档 | 内容 | 上限 |
|---|---|---|
| 中等 | 增删查、余额、CSV 导入导出、月报，32 条测试 | 60 次模型调用，1800 秒 |
| 完整 | 再加删除、日期范围、标签、预算、周期记账、所有状态存在同一个文件，1 万行的性能要求，73 条测试 | 200 次模型调用，7200 秒 |

## 结果

| | 中等 | 完整 |
|---|---|---|
| 我的测试复跑 | **32/32**（3 遍） | **73/73**（3 遍） |
| `tests.sh` 被改过吗 | 没有 | 没有 |
| 墙钟时间 | 约 32 秒 | 约 5.7 分钟 |
| 模型调用 / 工具调用 | 12 / 11 | 126 / 126 |
| 模型时间合计（中位数、最长） | 29.4 秒 | 281.7 秒（1.5 秒、34.8 秒） |
| 工具时间合计 | 0.85 秒 | 11.6 秒 |
| 输入 token（其中命中缓存） | 10.2 万（9.1 万） | 382 万（372 万，97%） |
| 输出 token | 约 5600 | 约 4.4 万 |
| 单轮最大输入 | 约 1.1 万 | 约 5 万 |
| 切片 | 2 | 11 |
| 退出码非 0 的命令 | 0 | 6（跑测试时没通过，随后改好） |

完整那次的实现：导入 1 万行 63 毫秒，`report` 21 毫秒（参考实现分别是 51 和 13 毫秒）。它的存储设计和参考实现几乎一样：
一个文件里放多种带类型标记的记录，金额按「分」存成整数。

端点没有配置单价，平台没有算出钱数，实际花费以 DeepSeek 控制台的账单为准。完整那次输入里 97% 命中了缓存。

## 完整那次经历的事件

- **12:32:05 模型调用重试一次：** 原因是 `max_output_reached`，一次输出写满了 8192 token。平台自动重试，没有续写。
- **12:33:41 优雅重启 worker（`docker restart`）：** worker 正常结束当前切片，Run 回到 `queued`，2 秒后被新 worker 接手。没有中断。
- **12:33:58 硬杀 worker（`docker kill`）：**
  - 12:34:16 租约过期，Run 被打断；
  - 12:34:17 恢复被批准并重新拿到租约；
  - 12:34:19 新沙箱建好，从检查点恢复工作区；
  - 之后接着做完了，从崩溃到恢复约 19 秒，基本就是租约过期时间。
- **12:36:05 上下文压缩一次：**
  - 前 97 条消息压成摘要，摘要这一次调用输入约 2.9 万、输出约 2300 token；
  - 之后单轮输入从约 5 万降到约 3.4 万，模型照样完成了任务。
- **12:36:59 完成：** 两个沙箱预约都已释放，没有残留容器。

## 发现的问题

- **中等那次发现：** Run 最后一片只是回答、没有用沙箱时，前一片冻结保留的沙箱在 Run 完成后没被销毁，要等 5 分钟才被回收。违反产品
  设计 §1526。修复见 #161。
- 完整那次没有发现新问题。

## 这一遍没能证明什么

- **#161 修的那条路径这次没有被走到：** 完整那次最后一片仍然用到了沙箱，所以是按原有逻辑销毁的。「Run 结束时没有残留」这一点，不能当成
  #161 在真实栈上生效的证据。
- **只跑了一个任务、一个模型：** 结果只说明这类「规格清楚、有测试」的编程任务能做完，不说明开放式任务的表现。
- **任务比预想的快：** 完整那次 5.7 分钟就做完了，离 7200 秒的执行上限很远。超过一小时的真实任务这次没有测。
- **崩溃只测了一种：** 只在模型调用阶段硬杀过 worker，没有在工具正在执行、或者检查点正在提交时杀。

## 不声称什么

- 不声称真实长任务在生产上同样稳定：这是一台开发机、一个工作空间、一个并发的 Run。
