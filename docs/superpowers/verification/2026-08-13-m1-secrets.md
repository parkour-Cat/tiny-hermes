### 3.1 Envelope and persistence

- `seal` / `unseal` round-trips AES-256-GCM. The DEK is wrapped with the KEK
  and `key_id` as associated data. The all-ones test KEK
  (`AQEBAQEBAQEBAQEBAQEBAQEBAQEBAQEBAQEBAQEBAQE=`) does not yield plaintext
  from a row wrapped with the all-zeroes KEK
  (`AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA=`). A swapped `key_id` also
  refuses. A short KEK is refused at decode.
- Table `secrets` has no plaintext column. Platform rows require
  `workspace_id IS NULL`. Uniqueness is two partial indexes: workspace
  `(workspace_id, name) WHERE scope='workspace'`; platform
  `(name) WHERE scope='platform'`. PostgreSQL UNIQUE would treat NULL
  `workspace_id` as distinct, which is why a single unique constraint is
  not used.

### 3.2 HTTP: create, list, disable, rewrap

```text
POST   /api/v1/secrets                 { name, scope, plaintext }
GET    /api/v1/secrets                 names, mask, scope, status, timestamps
POST   /api/v1/secrets/{id}/disable
POST   /api/v1/secrets/rewrap          before /{id}/disable
```

- Create returns a mask (first/last 2 characters, rest bullets). Listing and
  disable responses have no plaintext, ciphertext, nonce, or wrapped DEK.
- Duplicate name is 409 `secret_name_taken`. Missing KEK on write is 503
  `kek_missing`. Viewer 403. Developer lists names, cannot write.
  Workspace admin writes workspace secrets, not platform. Platform admin
  writes platform secrets (audited `secret.platform_write`).
- A platform admin who is a **developer member** of a workspace still cannot
  write that workspace's secrets: membership is checked first. Same rule as
  machine identity.
- Disable leaves ciphertext in place. There is no GET-plaintext route.

### 3.3 Ready, overlap, model call

- API `/health/ready` includes `kek: current` or `kek: missing` and is 503
  when missing. Settings default `tiny_hermes_kek` is `""` so a Worker still
  boots; unwrap at call time then fails that call.
- `credential_ref` is an env-var name (`^[A-Z][A-Z0-9_]*$`) **or** a Secret
  UUID. The env grammar cannot contain a hyphen, so the two never collide.
  Registration accepts a set env var **or** an active Secret id. A pasted
  looking-like-a-key string is 422.
- `CredentialResolver.resolve` unwraps an active Secret. The wrong KEK raises
  `CredentialMissing` and leaves ciphertext / wrapped DEK / `key_id`
  unchanged. A disabled Secret is not available.
- `ModelRouter` unwraps in the same session and passes the token into
  `OpenAICompatibleProvider`. The live Compose stack was not running, so a
  full model round-trip through a Secret-backed endpoint was not executed
  here. Registration + resolver + router wiring are what this slice proved.

### 3.4 Rewrap

- Rewrap unwraps the DEK with the previous KEK and wraps with the current.
  Ciphertext and nonce are not re-encrypted.
- Two rows, interrupt after the first `replace_wrap`, rerun: the already-new
  `key_id` is skipped; the remaining row finishes. Response
  `{ processed, remaining, current_key_id }`.
- No previous KEK: 503 `previous_kek_missing`. Workspace admin cannot rewrap.

### 3.5 Console

Nav is Agent / 运行 / 成员 / 模型端点 / API Keys / Secrets. Approvals is
absent. Create form types plaintext once. After create the list shows the
mask; GET handlers never return plaintext. Rewrap is shown only when
`is_platform_admin`. Covered by Vitest + MSW, not Playwright.

### 3.6 Compose credential form

Local Compose still passes `TINY_HERMES_MODEL_KEY_EXAMPLE` on `x-app-env`.
That is the 3A env-var overlap path. `TINY_HERMES_KEK` (32 zero bytes,
standard base64) is also on `x-app-env` only. The Controller keeps
`*base-env` and therefore does not receive the KEK, MinIO keys, or the
model-key passthrough.

To exercise rewrap against Compose, an operator must create a **platform**
Secret (console or `POST /api/v1/secrets` with `scope: platform`) and
register an endpoint whose `credential_ref` is that UUID. This environment
did not do that.
