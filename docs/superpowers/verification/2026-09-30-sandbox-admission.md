# 沙箱内存准入与禁止 swap：让整个栈宕掉的场景，现在平稳跑完

日期 2026-09-30。分支 `feat/capacity-acceptance`，未推送。规格 v2.14（`fefb59f`）。实现从
`74ff2ec` 到 `ef21a03`，测试和实现分开提交。

## 为什么有这一遍

[OOM 记录](2026-09-30-sandbox-oom.md)：24 个沙箱各常驻 400 MiB（合计 9.6 GiB），8 GiB 的主机
13 秒内耗尽内存，OOM killer 杀掉了 `dockerd`，整个栈都停了。原因是没有任何东西限制沙箱内存的
总和。

产品负责人定了三件事：
- 按内存**上限**之和准入，不按实际用量；
- 默认预算取主机内存的一半；
- 每个沙箱的上限保持 1 GiB，改成可配置。

## 改了什么

- **配置**：新增 `SANDBOX_MEMORY_MB`（默认 1024）和 `SANDBOX_MEMORY_BUDGET_MB`。
  - 预算不填（或 Compose 传来空字符串）表示取主机内存的一半，由 controller 启动时读
    `/proc/meminfo` 算出。
  - 预算小于一个沙箱时拒绝启动，并在错误信息里写明该改哪个配置。
- **记账**：实例记下自己创建时的内存上限（迁移 0067，已有的行回填 1024）。已占用内存 =
  所有「预留还有效」（active、kept、isolated）的实例的上限之和。
- **准入**：controller 在新建实例前，拿一把 Postgres 事务级 advisory lock，锁住
  「数 → 建容器 → 登记」这一整段，直到事务提交。
  - 放不下时，先回收其他 Run 的冻结沙箱（按保温到期时间从早到晚）。只挑「预留 KEPT 且实例
    FROZEN」的，因为解冻后预留仍是 KEPT，只看预留会误删正在运行的沙箱。
  - 回收了也放不下时，一个都不回收，直接以 `memory_budget_exhausted` 拒绝。
  - 同一 Run 解冻自己的冻结沙箱不计入准入。
- **防竞争**：解冻方先 `FOR UPDATE` 锁自己的预留行；回收方用 `FOR UPDATE SKIP LOCKED` 跳过被锁的
  行，所以不会删掉正在被解冻的容器。回收时容器已经不在（例如被调度器同时清掉）算成功。
- **Worker**：收到 `memory_budget_exhausted` 时结束时间片，把 Run 放回 `queued`，不算失败；
  然后这条通道暂停一个空闲轮询间隔（默认 2 秒）再领取。暂停用普通等待而不是唤醒通知，因为每来
  一个新 Run 都会发唤醒，恰恰是没有空间的时候。
- **禁止 swap**：沙箱的 `memswap_limit` 等于 `mem_limit`。
- **Compose**：把两个配置项传给 controller。

## 测试过了

- 后端单元测试 2499 条通过；沙箱集成测试 107 条通过，其中新增 8 条准入测试、8 条存储层测试、
  1 条引擎测试。
- **并发测试是有效的**：两个申请同时抢最后一份额度，只有一个能成功。
  - 临时去掉准入锁后连跑 5 次，5 次都失败；
  - 加上锁连跑 5 次，5 次都通过。
- **退避测试是有效的**：只实现「放回队列」而不暂停时，一条通道 1.5 秒内调用了 116 次 acquire；
  加上暂停后是 1–2 次。
- 完整的本机 CI 镜像：结果见文末。

## 走通了什么

**controller 实际生效的配置**（在容器里调用同样的函数算出）：每个沙箱 1024 MiB，预算
4002 MiB（VM 的 8005 MiB 的一半），预算环境变量为空时读成 None，controller 正常启动。
迁移 0067 已执行。

**重跑让栈宕掉的那个场景。**24 个长任务，每个沙箱常驻 400 MiB；2 × 16 条通道；每秒 3 条短消息，
持续 150 秒；模型延迟 2 秒。为了能在合理时间内跑完，每个长任务 20 轮（OOM 那次是 60 轮；OOM
发生在开始后 13 秒，远早于任何一个任务跑完）。

| | 没有准入（OOM 那次） | 有准入 |
|---|---|---|
| 结果 | 13 秒内内存耗尽，`dockerd` 被杀，整个栈停止 | 474 / 474 完成，没有失败 |
| 同一时刻的沙箱最多 | 24 | **3**（4002 ÷ 1024） |
| 沙箱内存合计最多 | 约 9.6 GiB（写入中） | 1207 MiB |
| VM 占用最多 | 可用内存只剩 160 MiB | 43% |
| swap 增加 | 约 7–8 GiB | 0 |
| 内核新增的 OOM 记录 | 有，最后杀到 `dockerd` | 0 |
| 死锁 / Postgres ERROR / Worker 报错栈 | —— | 0 / 0 / 0 |

- 回收了 22 次（审计里的 `sandbox.evict`），正好等于缓存重置 46 次减去最初的 24 次。
- 模型轮次 954 = 450 + 24 × 21，工具调用 480 = 24 × 20：**被拒的尝试没有花掉任何一次模型调用。**

**禁止 swap 的行为对照。**用同一个沙箱镜像，内存上限 256 MiB，往 tmpfs 写 384 MiB：

| | MemorySwap | 结果 | 容器 |
|---|---|---|---|
| Docker 默认 | 512 MiB | 写成功（借了 swap） | 仍在运行 |
| 等于上限 | 256 MiB | 写不进去 | 整个容器被 OOM 杀掉（`OOMKilled=true`） |

压力留在了那一个沙箱里，它的 tmpfs 也随容器一起释放。

## 代价与发现

1. **不用工具的短消息变慢了。**排队 P95 从 0.02 秒变成 2.0 秒，端到端 P95 从 2.1 秒变成 4.1 秒。
   通道在工具 Run 被拒后暂停 2 秒，这段时间里短消息也领不到。仍在「10 秒以内」这条标准里，
   但这是实打实的退化。
2. **被拒的循环很频繁。**
   - `run_lease_acquired` 有 4923 条，正常约 500 条，多出来的约 4400 次都是「领到 → 被拒 →
     放回队列」，约每秒 11 次。
   - Postgres CPU 中位数 101%。这一轮是 20 轮的长任务，和单机档验收（60 轮）不完全可比，
     所以不给「涨了多少」的数字。
   - 每次被拒都会往那个 Run 的事件记录里写一条，平均每个长任务多了约 180 条，时间线上是噪音。
   - 可能的改法：没有空间时，领取查询先跳过要用工具的 Run；或者给被拒的 Run 一个「最早何时再试」；
     或者被拒的尝试不写事件。都还没做。
3. **这台 VM 同时只能有 3 个带工具的沙箱。**这是按上限准入的代价，也是事先说好的取舍。运维可以
   调低 `SANDBOX_MEMORY_MB` 换更多个数。
4. **整个项目的日志都看不到 `extra=` 字段。**`configure_logging` 的格式是 `%(message)s`。
   controller 启动时记下的预算、Worker 记下的拒绝原因和 run_id，都没有打印出来。
5. **`SANDBOX_START_ATTEMPTS` 定义了，但没有任何代码读它。**

## 这一遍没能证明什么

- 沙箱在自己内部被 OOM 杀掉之后，它所在的 Run 会怎样（失败、中断，还是恢复），没有测。
- 「内核没有新增 OOM 记录」是读内核日志缓冲区得出的，而缓冲区会滚动，这个证据偏弱。更强的
  证据是：swap 没有增加，VM 占用最多 43%。
- 回收和解冻之间的竞争，只在存储层测过（`SKIP LOCKED`）。现场那一轮回收了 22 次、没有失败，
  但那不是一个专门制造这种竞争的测试。
- 预算来自 controller 容器里读到的 `/proc/meminfo`。在装了 lxcfs、或者给 controller 容器设了
  内存上限的主机上，它读到的可能不是主机的总内存，这种情况没有测。
- **只适用于单机。**准入锁和已占用内存的总和都是整个数据库范围的；以后有多台沙箱主机时，每台
  主机要有自己的预算，这里的做法就不对了。
- 只在 OrbStack 上测过，每种场景只跑了一次。

## 不声称什么

- 不声称短消息多出来的约 2 秒，对所有部署都可以接受。
- 不声称默认预算（主机内存的一半）适合所有主机。
- 不声称这套准入适用于多台沙箱主机。

测完之后，栈已经恢复成 1 个 Worker、`WORKER_CONCURRENCY=1`、模型延迟 50 ms、调用上限 20，
没有遗留的沙箱。
