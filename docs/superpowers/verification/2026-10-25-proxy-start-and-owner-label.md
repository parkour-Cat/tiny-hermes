# 代理一启动就连回沙箱网络；栈不再清扫测试的容器

日期 2026-10-25。分支 `fix/proxy-reattach-on-start`。

## 一、代理一启动就连回

#154 之后，代理被重建只能等定期清扫把它连回去，默认最长 5 分钟。现在 controller 订阅 Docker 里代理容器的
`start` 事件，收到就清扫一次。定期清扫保留作兜底。事件流结束时（例如守护进程重启），5 秒后重新订阅。

## 二、栈的清扫在删测试的容器

做第一项时，沙箱集成测试偶发失败。比如命令在超时之前就以 137 退出，而且两种运行时都出现过。

**原因：** 开发机上正在跑的 Compose 栈，它的 controller 不带标签过滤，看得到整台 Docker 上的平台容器。测试的容器
不在栈的数据库里，就被当成「没有记录」删掉了。

**证据：**
- 栈的 controller 日志一直有 `sandbox host swept containers=1`，审计表里扫掉的 Run 都不在栈的数据库里；
- 把栈的清扫调到每 10 秒一次后，失败更容易出现。

这和 10 月 24 日压测那次正好反方向：那次修好了「测试不碰栈」，没有修「栈不碰测试」。

**改了什么：**
- 新增归属标签 `tiny-hermes.owner`。带这个标签的资源，只有带同样标签的引擎才列得出来。部署里的引擎不带它，所以不碰
  这些资源；没有这个标签的资源，照旧列出。Docker 的过滤器表达不了「不带某个标签」，所以在列出之后判断。
- 测试共用的 `LABEL` 改成这个归属标签。另有三个测试文件各自写死了旧标签 `tiny-hermes.test`，一并改掉。这是用
  「每秒列一次没有归属标签的容器」抓出来的。
- 测试里扮演「别人的容器」的那一个，改成带另一个归属值。它原来不带标签，栈也会去删它。

## 测试过了

- 真 Docker：
  - 不调用清扫，删掉代理并按同名重建，几秒内沙箱又能按名字连上代理（**改之前失败**，监听函数不存在）。两种运行时
    都跑了。
  - 部署引擎列不出带别人归属标签的容器和卷，带这个标签的引擎列得出（**改之前失败**）。
- 栈的清扫设成每 10 秒一次，同时跑沙箱集成测试：
  - 改之前：前后 4 遍里有 2 遍出现偶发失败，栈的清扫多次删掉测试的容器；
  - 改完：
    - 最后一遍 309 passed、1 skipped；
    - 这一遍里，每秒检查一次，没有出现一个不带归属标签的测试容器；
    - 栈的清扫一次都没有删掉东西。

    中途还抓到过一个漏网的（上面那三个写死旧标签的文件），改掉之后才干净。
- 之前偶发失败的超时测试，连跑 5 遍全过。单元测试 2767 passed。
- 测完把栈的清扫间隔恢复为默认。

## 这一遍没能证明什么

- 订阅事件这条路只在测试里、本机 Docker 上走过。生产上守护进程重启后能不能重新订阅，没有真的重启过守护进程去验。
- 归属标签是靠约定生效的：谁给生产资源打了这个标签，生产的清扫就看不见它。运维手册 §17.2 写了这一点，但代码不拦。

## 不声称什么

- 不声称所有偶发失败都来自栈的清扫：这次只找到了这一个原因，修完后连跑的几遍都是干净的。
