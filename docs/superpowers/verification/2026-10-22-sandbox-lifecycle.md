日期 2026-10-22。分支 `fix/sandbox-lifecycle`。来自同一次只看代码的架构审查，接着
[Compose 那一遍](2026-10-22-compose-hardening.md)。运维手册 §8.7。

| 改了什么 | 测试 | 实现 |
|---|---|---|
| 工具超时真的停掉命令和它起的子进程；输出边读边截断 | `58c20ed` | `5c67ffe` |
| controller 启动时和每 5 分钟清扫没有记录的容器、没人拥有的数据卷；新实例拿空卷 | `1a3b15b`、`7aec150` | `ae23afa` |

## 为什么有这一遍

审查发现了四个问题，每一个都在这一遍里先写测试复现了，然后才改：

- **超时不停命令。**`asyncio.wait_for` 套在 `to_thread` 上，超时只是不再等那个线程，exec 照样在
  容器里跑，告诉模型的却是「已停止」。`npm run dev` 这类命令会跟着沙箱冻结、再跟着解冻，一直
  活到 Run 结束。读输出的线程也一直占着，非流式那条路径还把输出全部读进内存才截断。新测试在
  修复前直接挂住：被放弃的线程阻塞到容器被删为止，这正是这个问题本身。
- **容器泄漏。**`acquire` 先 `docker run`，再在同一个事务里写记录。两步之间崩溃或者提交失败，
  容器就一直跑着，不在内存预算里，也没有任何代码按标签找它：`volumes_labelled` 一直没有调用方。
- **复用旧卷。**冻结实例过期被丢弃，或者被驱逐时，卷留着；下一个实例挂的还是这个卷，恢复时直接
  解包在旧文件上。测试复现了：旧卷里的 `leftover` 在新实例里还在。按工作区设计 §7，恢复要在
  空卷上做；多出来的文件会让恢复后的扫描和清单对不上，Run 判成 `workspace_integrity_failed`，
  而且不能重试。
- **工具副作用被重放。**崩溃恢复只看模型那一侧给的 `replay_safe`。一轮里 `http.*` 的 POST
  已经到了对方，Worker 在这一轮记账之前被杀掉，恢复就会让模型从同一份对话重来，写操作再发一遍，
  最多重发 `max_recovery_attempts` 次。

## 怎么改的

- **超时**：命令在容器里套一层 coreutils `timeout --kill-after=2 <秒数>`。`timeout` 让自己成为
  进程组组长，到点给整个进程组发 TERM，2 秒后发 KILL，所以命令在后台起的 `sleep &` 也一起停。
  controller 自己的等待改成截止时间再加 7 秒，只作兜底。输出读到上限后就只计数、不再保存。
  退出码 124 判为超时；137 只在用时达到截止时间时才算超时，否则可能是被 OOM 杀掉的。
- **清扫**：`SandboxController.sweep()` 在准入锁下进行：
  - 容器带 `tiny-hermes.run` 标签，但没有一条未销毁的实例记录指向这个容器 ID，就删掉；
  - 卷带这个标签，但它的 Run 既没有占用中的记录也没有租约，就删掉；还被挂载、删不掉的卷留着，
    记一条日志。
  - 每次删除都写审计（`sandbox.sweep`）。controller 启动时先扫一遍，之后每
    `SANDBOX_SWEEP_SECONDS`（默认 300）扫一遍，某一遍失败只记日志。
- **准入锁**：`_admit` 原来在没配内存预算时不拿锁，现在总是先拿锁。清扫敢把「没有记录的容器」
  当成孤儿，前提是每个 `acquire` 从 `docker run` 到记录提交都拿着这把锁。
- **新实例拿空卷**：`acquire` 建卷之前，先删掉这个 Run 留下的所有容器和它的卷。
- **效果未知**：`reserve_tool_call` 本来就在每次工具调用发出前执行，锁着 Run 行、检查租约。它
  多了一个参数 `reaches_outside`，为真时在同一个事务里把 `checkpoint_effect_status` 设成
  `unknown`；这一轮记账时 `record_slice` 会重新写成 `none`。哪些调用算触达外面：
  - 所有 `http.*`，GET 也算：读操作不改东西是对方的承诺，平台核实不了；
  - 所有 `mcp.*`；
  - Agent 配了网络时的 `shell.exec`。
  - 没配网络的 `shell.exec` 和 `file.*` 不算：它们只能改工作区，恢复会回到最后提交的版本。

## 测试过了

- 后端单元测试 2615 条通过；集成测试（含 sandbox 目录）1205 passed、1 skipped（原有的 TLS
  socket 权限那一条）；ruff、pyright 0 errors。
- 新的集成测试（真 Docker、真 Postgres）：
  - 超时：`sleep 1001 & sleep 1000` 超时之后，容器里两个 sleep 都没有了（非流式、流式各一条）；
    超时之前打印的内容保留在结果里；`yes` 的输出在上限处截断。
  - 清扫：没有记录的容器被删，有记录的留着；没有占用记录也没有租约的卷被删，冻结保留中的 Run 的
    卷留着，有租约的卷留着；保留过期之后新实例看不到旧文件；Run 自己留下的没有记录的容器，在它
    下一次 `acquire` 时被删。
  - 效果未知（真 Worker、真代理、替身 API）：配了网络的 `shell.exec` 执行时这一列是
    `unknown`，这一轮记账后回到 `none`；没配网络的始终是 `none`；`http.*` 的 GET 和 POST
    到达对方时都已经是 `unknown`。
- 单元测试：没配预算的 `acquire` 也拿准入锁；controller 启动时就扫，一遍失败下一遍照样扫。
- 本地栈：用新镜像重建 controller 之前，手动放了一个没有记录的沙箱容器和它的卷。controller
  启动后日志打出 `sandbox host swept containers=1 volumes=1`，容器和卷都没了。

## 这一遍没能证明什么

- **离开进程组的子进程不会被停掉**（`setsid`、自己 daemonize 的服务）。它们照旧活到容器被删。
  运行时镜像里没有 `setsid`，但 bash 能做到差不多的事。
- **每个被批准的镜像都必须带 `timeout`。**平台自己的镜像有（coreutils）；运维换成别的镜像而
  没有 `timeout`，所有命令都会失败。没有加启动时的检查。
- 清扫只在单机栈上手动放了一次孤儿容器。没有真的在 `docker run` 之后、提交之前把 controller
  杀掉来造孤儿。
- 「有记录没容器」（驱逐回滚、手工删容器）只在保留中的实例上处理了：下一次 `acquire` 改为建新
  实例，有测试，修复前这条测试失败。冻结中、隔离中的记录对应的容器没了，仍按原来的路径走
  （Scheduler 回收）。
- **效果未知会让更多 Run 在崩溃后直接失败，而不是自动恢复**：用了 HTTP、MCP 或联网 shell
  的 Run，只要崩溃发生在这一轮记账之前就是这样。这是有意的取舍（宁可失败，也不重发一次写），
  但它改变了这些 Run 的恢复率，没有量过。派生重试也会因此拒绝（`retry_not_safe`）。
- 委派出去的子 Run，判断用的是它自己 Agent 规格里的网络配置，没有按委派时收窄后的权限再算。
  这样只会多标，不会漏标。

## 不声称什么

- 不声称工具调用现在是「恰好一次」。它保证的是崩溃后不会**自动**再发；记账之前的那一次到底
  有没有生效，平台仍然不知道。
- 不声称沙箱隔离变强了。runc、共享内核、同主机沙箱之间网络互通，这些都没动。
