# 压缩之后,还能搜得回来 — 2026-08-25

> 产品:v2.5 §7.4.2(上下文分段与压缩)、§14.3(会话搜索)、§19.1。
> 起因:「用户只有这个窗口跟机器人对话,几十天的消息你怎么处理」。

## 1. 之前是什么状态

窗口装不下时,老对话被压成一条摘要。那条摘要说的是:

> Messages 1-40 (40 in total). They were: 20 assistant, 20 user.
> Tools called: file.read x3.

**它不说聊了什么。** 模型知道自己忘了(摘要明写着),但**搜不出它不知道存在的
东西**——`session.search` 需要一个词,而那个词唯一的来源,正是刚被移出上下文的
那段文本。

## 2. 一个约束改变了实现方式

原计划照 Hermes 的做法:调模型按模板生成摘要。开始之后读到 `_summarize` 的
docstring:

> **No model call**: ... a deterministic summary ... replaying the same Run
> produces the same context.

这不是风格选择。这个平台会恢复中断的 Run(`SchedulerRuntime._recover_interrupted`),
**模型生成的摘要会让同一个 Run 在第二次尝试时看到不同的上下文**。

所以这一版做的是纯函数能做的那半:**提取**,不是**生成**。

中文按二元组提取,和迁移 0045 索引中文的方式一致——**这也是为什么必须先修中文
搜索**:在那之前,任何中文线索都是搜不出来的死字。

## 3. 一个老测试抓到了我没想到的权衡

加上线索之后,`test_the_summary_says_what_it_replaced_and_where_to_find_it`
**不再压缩了**。线索占的 token 让摘要装不下,压缩整个失败。

失败的后果不是「没有线索」,而是 §7.4.2 让 Run 进入 `context_overflow` 暂停,
**人什么都拿不到**。

所以优先级定了:**装得下 > 可检索**。现在先试带线索的摘要,整轮不行就退回不带
线索再试一轮。

## 4. 一条我写错了 docstring 的测试

`test_hints_are_searchable.py` 第一版的 docstring 声称它证明「提取粒度和索引
粒度一致」。

**它不证明。** 把提取改成三元组,两条测试照样通过——因为 `matching()` 会把查询
本身也过一遍 `th_cjk_bigrams`,任何粒度的线索进来都会被重新切开。

这其实是**稳健性而不是缺口**:线索不需要和索引一致,只需要是对话里出现过的
文本。但 docstring 说的不是这件事,所以它是一条声称了代码没有的保证的注释——
改掉了。

它确实有牙齿的地方:把线索换成不相关的词,两条都挂。

## 5. 破坏性验证

| 打掉什么 | 挂了几条 |
|---|---|
| 线索不进摘要 | 3 |
| 去掉「装不下就退回无线索」的重试 | 1 |
| 线索换成不相关的词 | 2 |

## 6. 这一遍没能证明什么

- **compose-e2e 没有重新取得绿色。**
- **没有对着真实的长对话跑过。** 所有测试里的会话都是两三条消息人为压缩的;
  一个真的聊了几十天、触发过多次压缩的会话,线索质量如何,**没有观察过**。
- **多次压缩的累积行为没有验证。** 第二次压缩会把第一次的摘要(包含线索那句)
  当作普通文本再提取一遍,于是线索可能自我强化或漂移。**这个行为没有测试,
  也没有设计过。**
- **线索的质量没有任何度量。** 「出现两次以上」是个粗糙的判据;它会漏掉只说过
  一次的重要事实,也会留下高频的无意义搭配。没有对照实验。
- **模型会不会真的去用这些线索,完全没验。** 摘要里写了「searchable with
  session.search」,但模型是否据此发起搜索,只有真实长对话能回答。
- **偏好类内容仍然只走 `memory.remember`**,需要模型主动想起来记。这一版没有
  改变那条路径,也没有让它更容易被触发。

## 7. 明确没做的

**模型生成的语义摘要**(Hermes 那套)。它和 §2 的重放确定性正面冲突,需要
单独设计:摘要在压缩时生成一次并持久化,重放时读存下来的那一份。那是独立的
一块工作。
