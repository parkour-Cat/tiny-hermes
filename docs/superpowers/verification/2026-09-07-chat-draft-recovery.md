# 聊天草稿刷新恢复验收

日期：2026-09-07。用户授权继续完善使用体验，本轮依据 [实施计划](../plans/2026-09-07-chat-draft-recovery.md)，完成聊天文字草稿恢复。基线为 `d88585f`；改动仅本地提交，不推送或合并。

## 本轮行为

- 在同一标签页刷新，恢复尚未发送或发送失败的文字，不自动提交。
- 服务端通过只读 `/api/v1/end-user/me` 返回当前 cookie 对应的终端用户和工作空间；确认身份后，才按用户、工作空间、Agent 和会话恢复草稿。缓存身份不能提前显示旧草稿；重新核实时暂时隐藏聊天，保留已挂载的输入状态。
- 首次发送创建会话时，先迁移草稿和重试状态，再切换地址。发送成功清理草稿；响应丢失后的相同请求跨刷新沿用原标识，避免重复执行。
- 主动清空文字后，相同文字再次输入视为新的提交，不沿用此前请求标识。
- 刷新后附件文件需重新选择；页面列出文件名，重新选择或明确移除占位后才能发送，避免用户误以为附件已恢复。
- 从本机列表移除会话时清理对应草稿；清空本机记录及成功抹除自己的数据时，清理当前标签页草稿。
- 浏览器无法保存输入时提示先复制。若发送状态无法保存，保持输入，并在创建任务前明确提示“本次未发送”；恢复可用存储后可以重试。

存储采用当前标签页的 `sessionStorage`。重试状态含准备提交的文本（包括已经拼入的文本附件内容），文件对象本身不保存。没有新增密码或凭据保存，没有改变终端用户授权范围和已发布 AgentVersion。

## 这一遍没能证明什么

- 不承诺关闭标签、浏览器重启或跨设备恢复；恢复依赖浏览器允许使用本标签存储。存储完全被禁用时，本轮会阻止无法安全记录状态的发送，并保留当前文字供复制。
