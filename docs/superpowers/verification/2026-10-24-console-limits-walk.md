# 控制台走查：运行上限和沙箱内存

日期 2026-10-24。分支 `fix/agent-page-feedback`。

「运行上限」设置页（v2.21）和 Agent 页的「沙箱内存」（v2.22）之前只有组件测试，从没在浏览器里打开
过。这一遍用 Playwright 驱动真的 Chromium，连本机 Compose 栈（控制台镜像重新构建过，之前的镜像是
25 小时前的），每一步截图，并读网络请求实际的请求体和响应体。

## 发现并修掉的问题

1. **保存被拒绝时，作者看不到。**错误条显示在页面最上方，作者在页面中部改字段，只看到输入框里还是
   被拒绝的值。现在被拒绝后错误条滚动到视野里并获得焦点。
2. **拒绝的说明是英文**，原样显示服务器的英文句子。现在四种「超过上限」的拒绝（沙箱内存、执行时间、
   模型调用次数、工具调用次数）都在响应的 `context` 里带上 `asked` 和 `allowed`，控制台用读者的语言
   自己说，并写明谁能调高；没有这两个数时，仍显示服务器的原句。
3. **「与当前版本的差异」列出了没改的三项**（`completion`、`context_budget`、`delegation`，显示为
   「— → null」）：表单把没有的项写成 `null`，后端会把两者规范化成同一份文档，差异列表却当成了改动。
   现在 `null` 和不存在视为相同。
4. 悬浮的「保存草稿 / 发布」操作栏在滚动时会盖住经过它下面的内容，这是固定顶栏的正常行为；修的是
   被程序滚动到的错误条，给它留出上边距（`scroll-margin-top`），不会落在操作栏下面。

### 修完之后在浏览器里再走一遍

从页面中部（滚动了 1084 像素）保存 8192：页面滚到错误条（滚动位置变为 30），错误条完全在视野里并且
有焦点，文字是「沙箱内存填的是 8192 MB，平台最多允许 4096 MB。需要更大的沙箱，请平台管理员调高上限。」
差异列表只剩真正的改动 `sandbox · memory_mb`（256 → 8192）。

## 测试过了

- 后端集成测试：四种超限拒绝的 `context` 都是 `{"asked": …, "allowed": …}`（其中模型调用和工具调用
  这两种以前没有经过 HTTP 的测试，这次补上）。
- 前端：四种拒绝用中文说出两个数；没有数字时显示服务器原句；`null` 和不存在不算差异；被拒绝的保存
  调用了滚动并把焦点放到错误条上。
- 先写测试、看它失败、再实现。「没有数字时显示原句」这一条一开始就通过，因为那是原来的行为，留着
  防止以后改坏。
- 全量（本地）：后端单元 2752 passed、集成 1335 passed；前端 406 passed；tsc、eslint 通过。

## 这一遍没能证明什么

- 只走了中文界面；英文文案只有单元测试。
- 只在 1400×1000 的窗口里走过，没有试窄屏。
- 走查用的是无界面浏览器。CLAUDE.md 提醒过它会被焦点和动画骗；这一遍的判断都基于响应体、数据库和
  截图里看得见的内容，「有焦点」用的是 `document.activeElement`。
- 「运行上限」页自己保存失败的情况（比如超过平台上限）没有走：输入框有 `max`，填不进去。

## 不声称什么

- 不声称控制台其他页面没有同样的问题。被拒绝时错误条在视野外，在别的长表单里也可能出现。
