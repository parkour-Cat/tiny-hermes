# C 档第 3 步：沙箱主机登记、心跳、地址池不重叠

日期 2026-10-23。分支 `feat/sandbox-host-registry`。[C 档设计](../specs/2026-10-22-tier-c-sandbox-host-pool-design.md)
§4.1、§4.6、§9 第 3 步。

这一步之后仍然只有一台沙箱主机在被使用：表里有了每台主机，但 Worker 还不读它（放置和路由是下一步）。

## 做了什么

| 部分 | 内容 |
|---|---|
| 迁移 0079 | 新表 `sandbox_hosts`：名字（主键）、对外地址、内存预算、地址池、状态（`active` / `draining` / `retired`）、最后心跳时间 |
| 登记 | controller 在开始服务之前写入自己的一行。已有的行只更新地址、预算、地址池和心跳，**不改状态**，所以被排空或下线的主机重启后不会自己回来 |
| 地址池 | 和另一台 `active` 或 `draining` 主机的地址池重叠时，controller 拒绝启动，报错里写出是哪一台、它的地址池是什么；`retired` 主机的地址池可以复用。登记在一把锁下进行，两台主机不会同时读到对方不存在 |
| 心跳 | 每 `SANDBOX_HOST_HEARTBEAT_SECONDS`（默认 10）秒更新一次；失败只记日志，下一次照常 |
| 配置 | `SANDBOX_CONTROLLER_ADVERTISE_URL`：其他主机连过来的地址，只允许 `tls://`；空字符串当作没有设置。Compose 已透传 |

## 测试过了

- 集成测试（真 Postgres）：登记写入的内容；重启后地址和预算更新、状态保持 `draining`；`retired` 重启
  后仍是 `retired`；和 `active`、`draining` 主机重叠的地址池被拒绝并写出对方的名字和地址池，被拒绝
  的主机没有留下行；`retired` 主机的地址池可以复用；不重叠的、没有地址池的都能登记；同一台主机重新
  登记自己的地址池不算重叠；**两台主机同时用重叠的地址池登记，只有一台成功**；心跳让最后心跳时间往前走。
- 单元测试：启动时登记的四个值来自配置；没有网络的主机不登记地址池；地址池重叠时 controller 以
  `SystemExit` 退出，信息里有对方的名字和地址池；对外地址只允许 `tls://`；空字符串当作没有设置；
  心跳失败一次后照常继续（这一条是写完代码后补的，没有见过它失败）。
- `alembic upgrade head` 后 `alembic check` 没有差异。
- **真栈**：用这个分支重建镜像，Compose 栈重启后，`sandbox_hosts` 里出现 `default` 一行（预算 4002，
  状态 `active`）；启动 25 秒后最后心跳是 4.9 秒前，说明心跳在更新。controller 的启动日志里多了
  `sandbox_controller_name=default`。

## 这一遍没能证明什么

- 真栈上没有配地址池（本机 `.env` 没有 `SANDBOX_NETWORK_POOL`），地址池重叠导致拒绝启动这一条
  只在测试里走过。
- 地址池只和数据库里登记过的主机比，不和宿主机自己的网络比；那一条仍然由 v2.21 的启动检查负责。
- 没有两台真的主机。

## 不声称什么

- 不声称现在能部署多台沙箱主机：Worker 和 Scheduler 还只找一台。
