# Compose 的默认值和出站代理；冻结沙箱复用后的出站身份

日期 2026-10-22。分支 `fix/compose-hardening`。来自一次只看代码、不看设计文档的架构审查，
这是其中改动最小的几条。运维手册 §7.2、§10。

| 改了什么 | 测试 | 实现 |
|---|---|---|
| 出站代理只拿基础环境；数据存储默认只发布在 127.0.0.1；`ENVIRONMENT` 传进容器，非开发环境拒绝 Compose 自带的默认值 | `59a11d3`、`28ad234` | `fad53cf`、本记录所在提交（报错文字） |
| 冻结后被下一个时间片复用的沙箱，重新登记出站地址 | `2beb36b`、`7d3ea01` | `06f4f9e` |

## 为什么有这一遍

审查发现的问题：

- **出站代理用的是 `*app-env`**：KEK、对象存储密钥、模型密钥都在它的环境里。它上面的注释
  写的是「没有对象存储凭据、没有模型密钥」。而它是沙箱唯一能发包的进程，请求解析是我们自己
  写的，解析出一个漏洞，这些就都交出去了。
- **Postgres、Redis、对象存储发布在宿主机所有网卡上**。Redis 没有密码，Postgres 的密码写死在
  文件里。
- **容器里没有 `ENVIRONMENT`**，所以全是 `development`：会话 cookie 从不带 `Secure`，默认值
  （包括 32 个零字节的 KEK）也都能通过校验。
- **冻结的沙箱被下一个时间片复用时，出站地址没有重新登记。**时间片结束时 `freeze` 删掉了
  地址行，复用走的是 `_thaw_if_warm`，它只解冻、不登记；Worker 对复用的沙箱也不调 `thaw`。
  所以第二个时间片起，在第一次写操作的检查点（它会 freeze 再 thaw）之前，代理把这个沙箱当
  作不认识的调用方，返回 407。只读、只联网的时间片整片都是这样。

## 测试过了

- 后端单元测试 2633 条通过；集成测试（含 sandbox 目录）1192 passed、1 skipped（原有的 TLS
  socket 权限那一条）；ruff、pyright 0 errors。
- 新测试：
  - 读 Compose 文件：出站代理的环境里没有 KEK 和模型密钥，S3 密钥是空的；三个数据存储的
    端口都以 `${DATASTORE_BIND_ADDRESS:-127.0.0.1}:` 开头；`ENVIRONMENT` 在基础环境里；
    Postgres 服务端和客户端用同一个密码变量；SeaweedFS 和应用用同一对 S3 密钥；
    `Settings` 拒绝的默认值和 Compose 文件里的 `:-` 默认值逐个相等。
  - `Settings`：非开发环境下，六个默认值每一个都被拒绝；开发环境下照常启动。
  - 控制器单元测试：freeze、keep、再 acquire 得到 REUSED，地址行回来了。
  - 控制器集成测试（真 Docker、真 Postgres、通过 API 建的真 Run）：同样的流程之后，用代理
    自己的 `SqlScopeDirectory.sandbox_claim` 拿 Docker 实际分配的地址去问，答案是这个 Run。
    **去掉修复，这一条失败**，确认过。
- 本地栈重建：数据存储端口只在 `127.0.0.1` 上；代理容器里 `TINY_HERMES_KEK`、`S3_ACCESS_KEY`
  都是空的，代理正常启动、监听 3128。
- 用 `ENVIRONMENT=production` 加默认值直接启动 `tiny-hermes-egress`：拒绝启动，报出是哪几项。

## 这一遍没能证明什么

- **沙箱之间网络互通，没有修。**它们在同一个 `sandbox-egress` 网桥上，`internal` 不管容器
  之间的流量。按 Docker 文档，关掉网桥的容器间通信（`enable_icc=false`）会把沙箱到代理的
  流量也断掉。**这一点没能在本机验证**：本机 OrbStack 根本不执行这个选项，`internal` 和
  普通网桥上关掉之后容器照样互通。真正的修法（每个沙箱一个网络，或宿主机防火墙规则）还要
  另做。Compose 文件里原来说「连不到别的 Run 的容器」的注释改成了实话，手册 §10 写了。
- 冻结复用这条 bug 是读代码、单元测试、集成测试确认的；**没有在完整栈上跑一个两个时间片、
  第二片联网的 Run 去看 407 消失**。集成测试问的是代理的查询本身，不是代理进程。
- `ENVIRONMENT=production` 下整个栈能不能正常工作没有跑过：cookie 带 `Secure` 之后，经
  http 访问非 localhost 地址的控制台会登录不上，这是预期的，但没有试。
- 已有数据的库改 `POSTGRES_PASSWORD` 只在手册里写了步骤，没有演练。
- Redis 仍然没有密码，只是不再发布到所有网卡。

## 不声称什么

- 不声称 Compose 部署现在可以直接用于生产。审查里的其余问题（沙箱隔离强度、工具超时不杀
  进程、容器泄漏、工具副作用重放等）都还在。
- 不声称默认值清单是完整的。它只覆盖 Compose 文件里用 `:-` 兜底的密钥，和写死的 Postgres
  密码。
