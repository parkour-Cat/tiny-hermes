# 每个沙箱一个网络

日期 2026-10-23。分支 `feat/sandbox-networks`。产品设计 v2.21 §1.21 第 4 条；设计：
[每个沙箱一个网络](../specs/2026-10-23-sandbox-networks-design.md)；运维手册 §10。

| 改了什么 | 测试 | 实现 |
|---|---|---|
| 每个沙箱一个 `internal` 网桥，只有它和出站代理；网段从地址池里随机取 /28；销毁和巡检时删网桥 | `a89625d`、`d54f16d`、`b3dc288` | `756f1f3` |
| controller 读网络配置：地址池不可用时启动失败，还设着旧变量时警告 | `4198540`（**写在代码之后**） | `756f1f3`、`874c4cd` |

## 为什么有这一遍

所有联网沙箱原来共用一个 `internal` 网桥。`internal` 去掉的是出网，不是互访：一个 Run 能连到
同主机上另一个 Run 在沙箱里起的端口。产品负责人在 v2.21 选了「每个沙箱一个网络」。

## 设计时更正的一件事

讨论时我说 Docker 单机能建「几百个网络」，这是错的。Docker 默认的地址池在一台机器上只能分出
大约 31 个网络。所以 controller 从新配置 `SANDBOX_NETWORK_POOL` 里自己分网段：每个沙箱随机取
一个 /28，Docker 说重叠了就换一个，最多试 8 次；`/16` 能分 4096 个。

## 测试过了

- 后端单元测试 2690 passed；集成测试（含 sandbox 目录）1264 passed、1 skipped；pyright
  0 errors；`ruff check` 通过。全量集成跑完之后又改了两处：网络配置改成启动时读一次
  （`874c4cd`）、Compose 把旧变量传进去（`47d27f5`）。之后重跑了全部单元测试（2690 passed），
  没有重跑全量集成。
- 真实 Docker 的新测试：
  - 每个沙箱一个网桥，网桥上只有这个沙箱和代理，并且是 `internal`；
  - **沙箱 A 连不到沙箱 B 起的端口**。对照：B 的监听在 B 自己里面是通的，说明「不通」是因为
    网络不可达，不是因为没有东西在监听；
  - 沙箱用代理地址里的名字 `egress-proxy` 连得到代理；
  - 沙箱仍然连不到公网；
  - 沙箱销毁后网桥不在了，代理也不再接在它上面；
  - 主机巡检删掉没有记录的网桥；
  - 联网的沙箱里命令照常执行。
- 单元测试：
  - 网段被占时，从池里换一个 /28 再试；
  - 代理按名字接到网桥上，顺序是先建网、再接代理、最后建容器；
  - 池里没有空位时拒绝，不会无限重试；
  - 读配置的几种情况：完整配置、没设地址池、只设了旧变量、地址池不可用。
- 原来那条「复用的实例再次被代理认出」的测试，改成在每沙箱网络上跑，仍然通过。

## 走通了什么

本机的 Compose 栈重建到这个分支，设 `SANDBOX_NETWORK_POOL=10.240.0.0/16`，用压测脚本跑带工具
的长任务。worker 开两条通道、模型延迟 3 秒，好让两个沙箱同时存在：

- 两个沙箱各有一个网桥：`tiny-hermes-sandbox-<实例 id>`，`internal=true`，网段分别是
  `10.240.224.48/28` 和 `10.240.108.16/28`，每个网桥上只有这个沙箱和 `tiny-hermes-egress-proxy-1`；
- 在真实沙箱里：
  - B 起的监听，在 B 自己里面是通的；
  - A 连 B 的地址：**不通**；
  - A 连 `egress-proxy:3128`：通；
  - A 连公网：不通；
- 3 个 Run 全部完成。结束后沙箱容器剩 0 个，沙箱网桥剩 0 个，代理只剩默认网络；
- `.env` 里只设了旧的 `SANDBOX_EGRESS_NETWORK` 时，controller 启动时记一条警告，只记一次。

测完之后栈已恢复成 `.env` 的配置。**注意：`.env` 里只有旧变量，所以本机栈现在的沙箱不联网**，
要联网得在 `.env` 里加 `SANDBOX_NETWORK_POOL`。旧的 `tiny-hermes_sandbox-egress` 网络还留在本机
Docker 里，没有删。

## 这一遍没能证明什么

- **CI 里第一次打开了联网沙箱**（`SANDBOX_NETWORK_POOL`）。之前 CI 从来没走过这条路，所以这次
  CI 的结果，也是这条路第一次在 CI 里跑。
- 没测过地址池真的被用满的情况（4096 个网桥），只用替身测过「池里没空位就拒绝」。
- 冷启动多了建网、接代理两次 Docker 调用，没有量具体多慢。
- B 档（controller 在沙箱主机上，代理也在那台主机上）没有在真实两台机器上验证。
- 出站代理接在每个沙箱网桥上，它的指标端口在每个网桥上都连得到。仍然靠 token 挡住（指标设计
  §4.2），这一遍没有重新验证。
- `_networking` 的单元测试写在代码之后，没有先看它变红。

## 不声称什么

- 不声称沙箱之间在所有层面都隔离了。这一遍只处理网络。同一个内核、同一个 Docker 守护进程
  仍然是共享的，那要靠 gVisor 这类运行时，留到多机方向确定后再定。
