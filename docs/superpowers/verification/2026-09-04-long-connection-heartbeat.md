# 控制台说出长连接此刻连没连着 — 2026-09-04

> 由来：2026-09-03 23:53 一根长连接的 socket 死了，十小时没恢复。控制台整晚
> 显示「长连接」。发现它的方式是第二天早上有人发消息发不出去，问了一句
> 「服务停了吗？消息发不出去」。

## 1. 那一列为什么会说假话

它显示的是**存的值**。这不是 bug，是那一列当时能拿到的全部——它自己的注释
就承认了：

> the response carries the stored transport and nothing about the running scheduler

所以缺的不是判断，是**数据源**：没有任何东西说「此刻」。

## 2. 为什么不从审计行推

审计行盖得住那一次：`_on_reconnecting` 写了 `disconnected`，重试失败写了
`connect_failed`。按「最后一条是什么」去推，那晚能推对。

**但 scheduler 被 `kill -9` 时一行都不写**，最后一条会一直停在
`reconnected`——正是「显示连着、其实死了」。心跳盖得住这一种：一个被杀掉的
进程留下的是一个**不再变新的时间戳**，不是 `NULL`。

所以读的人靠它**有多旧**判断，不靠它存不存在。

## 3. 五层

| 层 | 做什么 |
| --- | --- |
| migration 0056 | `channel_bindings.long_connection_seen_at`，可空、**不回填** |
| scheduler | 探活循环每 `HEARTBEAT_SECONDS`（60）写一次，只在 socket 确实通的那一刻 |
| domain | `long_connection_state()`，四态；`STALE_AFTER = HEARTBEAT × 3` |
| API | 响应体多两个字段，状态在后端算好 |
| 控制台 | 配置标签旁边多一格状态 |

**不回填**：现有绑定从没被这套机制证实过，编一个时间戳等于让它们声称一个没人
观察过的状态。`NULL` 读作「从未」，那是事实。

**判断在后端**：它依赖 `STALE_AFTER > HEARTBEAT`，而那两个数一旦隔着 HTTP
边界就没有任何东西能保证一起改。写成乘法而不是写死 180，就是让这个关系没法
被单独改坏。

**四态不是三态**：`not_applicable`（webhook 没有「连着」这回事）和 `never`
（配成长连接却从没连上过）必须分开。合并会让**最需要被看见的那一种**看起来
正常。

## 4. 真机走查（2026-09-04）

| 时刻 | |
| --- | --- |
| 13:20:31 | 最后一拍心跳 |
| 13:20:58 | 停掉 scheduler |
| 13:23:39 | 过 180 秒阈值 |
| — | **控制台显示红色「已断开」**（用户截图为证） |
| 13:28:51 | 起回 scheduler |
| 13:29:12 | 心跳恢复（21 秒） |

判据是**有人在浏览器里看见了它**，不是「后端算出了那个状态」——这个仓库栽过
五次的正是后一种。

走查同时暴露了一件事：那句灰字「重启 scheduler 后生效」紧挨着红色的「已断开」，
读起来像「重启就能修好」。那一次碰巧是对的，下一次连接因为别的原因断了就不是。
修在 PR #85——提示只留给 `never`。

## 5. 这一遍没能证明什么

- **只验过「进程被停掉」这一种断法。**网络分区（进程活着、socket 死了、SDK 在
  重连）没有走查过。那一种在测试里有（`_wait_while_alive` 那条），但真机上
  SDK 的 `RECONNECTING`/`RECONNECTED` 何时触发、成不成簇，仍然只有 2026-09-03
  那一次观察。
- **没验过心跳写不进去时会怎样。**`_beat` 吞掉一切异常并继续，这是有意的
  （心跳是给人看的，不该把 socket 带下来），但「库连不上时页面显示什么」没有
  被走查过——按规则它会在 180 秒后变成「已断开」，而 socket 其实还活着。
  **这是这个设计已知会说的一句假话**，代价是「宁可虚报断开，不虚报连着」。
- **60 秒和 ×3 都是判断，不是测出来的。**没有度量过一次心跳 UPDATE 的真实
  代价，也没有度量过漏一拍的实际频率。
- **`never` 的成因没有被区分。**凭据不对、另一个绑定占着进程唯一的 socket、
  scheduler 没重启，三种都显示同一格，页面不说是哪一种。

## 6. 不声称什么

- **不声称「连接中」等于消息一定送得到。**心跳只说：**写它的那个进程认为
  socket 是通的**。能证明对面收得到的只有真的收到一条消息。
- **不声称那句重启提示是诊断。**它只在 `never` 显示，而 `never` 有好几种成因，
  重启只是其中一种的解法。
- **不声称这一列会替人发现故障。**它是给看的人用的，没有任何告警——没人打开
  这个页面，它就还是不会说话。
