## 2. 每一项真正缺的是什么

三项里没有一项缺的是「一个新功能」。缺的都是**同一个形状**：数据早就写对了，
只是没有任何人够得着。

**审计导出**：`list_events` 一直在做作用域解析和脱敏，导出没有第二套查询——
它调的就是那一个方法。真正的坑在别处：第一版把 `MAX_EXPORT_ROWS` 传给了
`filter_for`，而 `filter_for` 会夹到 `MAX_PAGE_SIZE`。导出因此在任何行数下
都只返回 200 行，状态码 200，没有任何提示。
**这一版通过了当时文件里的全部测试**，因为没有一条测试种过第二页。

**治理审批队列**：`decided_by`、`decided_at`、`decision_reason` 从 §16.3 落地
那天起就写得好好的，没有任何路由读得到。管理员一答复，「谁答复的、为什么」
就离开了产品。§26 还要求 M2 之后评估**审批负担**——那是一个只有已决行才能
回答的问题。

**示例 Agent**：没有任何示例。

## 3. 做的时候撞到的两件事

**筛选被忽略比筛选报错更坏。** 拼错的 `status=aproved` 如果被悄悄丢掉，调用方
读到的是默认的 pending 队列，标题却是他要的那个——他会据此认为里面每一条都
被批准了。所以是 400，而且回话里不回显他输入的那个词。

**浏览器里过滤分页列表**，回答的是「我取回来的这些行没有匹配的」，而问题是
「这件事到底有没有发生过」。这两句话看起来一模一样。历史筛选一律由服务端做。

## 4. 示例 Agent 为什么长这样

§21 把它放在向导的第五步。跑到那一步时，部署里只有一个模型别名——所以示例
不能要网络、不能要 HTTP 工具、不能要 MCP 服务器、不能要技能。这不是为了简单，
是**需要这些东西的示例根本创建不出来**，有测试钉住。

值得读的是 `completion.expected_artifacts`：模型说自己做完了不算数，文件必须
真的在（§12.2）。一个「说完了就算完了」的示例会把这个平台最要紧的一条教反。

创建走 `create_agent` → `replace_draft` → `publish` 三个既有方法。直接写一行
已发布版本，就是第二条绕开 `publish` 检查的入口——这个仓库最常出的那种问题。

## 5. 飞书 WS 为什么还是没做

`2026-08-22-feishu-channel.md` 已经判过一次，这一遍**没有推翻它**：可验证的
那一半（两种传输归一化到同一个事件、信封解析、摄入与传输解耦、Webhook 侧完整
可用）当时就做完了。剩下的是真正的长连接、`lark-oapi` 依赖、卡片 JSON 渲染，
以及 §929 的断线补投演练。

没有真实租户，加一个跑不起来的容器和一段只能靠猜的 SDK 调用，是拿「代码存在」
冒充「这条路走得通」。§929 那个开放问题（补投保证不了时 Webhook 是否成为必需
兜底）**仍然开放**。

## 6. 这一遍没能证明什么

- **导出的 5 万行上限没有被真实数据量走过**。那条 413 是把上限临时压到 2 才
  测出来的——真实的 5 万行导出有多大、多慢，没有量过。
- **审批历史没有在有真实体量的工作空间里读过**。翻页、`has_more`、
  `created_at DESC, id DESC` 的全序都有测试，但都是几行数据。
- **示例 Agent 从来没有真的跑完一次 Run**。测试证明它能创建、能发布、viewer
  创建不了——没有证明那个模型真的会写出 `summary.md`，因为那需要一个真实模型
  接入点。`expected_artifacts` 的检查逻辑本身是 §12.2 早就测过的。
- **本机 17 条 sandbox transport 测试跑不起来**（macOS 的 `AF_UNIX path too
  long`：`/private/var/folders/...` 的临时路径超过 104 字节）。它们在 Linux CI
  上是绿的，但本机的「全绿」这一遍**不包含它们**。
