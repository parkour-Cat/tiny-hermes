# 待办计数与记忆入口验收

日期：2026-09-06。用户授权继续全产品使用体验整理，本轮聚焦 UX-16、17。

## 实现与权限依据

- 控制台待办数只包括当前账号可处理的管理员审批、技能提案、记忆审核。只读成员不请求这些处理队列；开发者只计可处理的工作空间技能提案；平台技能由平台管理员处理。
- 技能判断同时用于列表按钮和侧栏计数。依据 `skills/application/service.py` 的 WRITERS、`_writable`、`_require_writer`；接口返回的 approvable 仅反映扫描和提案状态，不代表当前用户有权发布。
- 有可处理队列读取失败时显示 `?`；审批响应 has_more 为真时显示 `N+`。处理一项后立即刷新计数，并在页面前台每 30 秒更新。
- 技能提案默认请求 `status=pending`，已批准与已拒绝独立查询、显示处理人和时间。接口当前返回该状态的完整列表，本轮没有虚构技能分页接口。
- 搜索对话移到“记录 → 搜索对话”，仍限工作空间／平台管理员。搜索失败不会显示成“没有结果”。
- 共享记忆直接写入移到 Agent 标题旁的按钮，窗口写明 Agent 名称，提交使用该 Agent 的 ID。此操作不需要发布草稿。管理员才看到该入口；记忆审核页保留搜索和 Agent 管理的去向链接。
- 记忆正文换行、限制展示高度；搜索任务链接缩短并保留完整 title，结果卡片保持间隔。
