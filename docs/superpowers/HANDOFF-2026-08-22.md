## 3. 环境：这些坑我每一个都踩过

**跑集成测试前必须有 PostgreSQL。** 我用的是独立容器，因为宿主机的 5432 会抢端口
（那次产生了 139 个假错误）：

```
docker run -d --name th-test-pg -e POSTGRES_USER=tiny_hermes \
  -e POSTGRES_PASSWORD=local-only -e POSTGRES_DB=tiny_hermes_test \
  -p 127.0.0.1:55432:5432 postgres:16
```

**两个 export 必须分开写。** 这一条害我损失过四个小时：

```bash
export TEST_DATABASE_URL="postgresql+asyncpg://tiny_hermes:local-only@127.0.0.1:55432/tiny_hermes_test"
export DATABASE_URL="$TEST_DATABASE_URL"
```

`export A=... B="$A"` 会在赋值前求 `$A`，于是 `DATABASE_URL` 是空的，然后留下一个
`idle in transaction` 连接，让下一次 pytest 挂起——**看起来像慢，实际是死锁**。

**永远只跑一个 pytest。** 我这一轮犯了三次：两个套件抢同一个数据库，两边都开始报
级联错误。症状是长时间没输出。诊断：

```sql
select pid, state, now()-state_change from pg_stat_activity
where state like '%idle in transaction%';
```

有孤儿就 `select pg_terminate_backend(<pid>);`，别等。

**macOS 上 greenlet 装不上**：SQLAlchemy 的平台标记覆盖 `aarch64` 而不是 macOS 的
`arm64`。装进 venv 就行，**不要改 `pyproject.toml`**。

**在中国大陆的机器上**：Docker Hub 要配 `registry-mirrors`；`ghcr.io/astral-sh/uv`
**不在** Hub 镜像覆盖范围内，要走 `ghcr.nju.edu.cn` 再 retag。已经写进
`docs/development.md`。

## 4. 约定

- **测试先写,看它红,再实现。** 提交分开：先 test 提交，再 impl 提交，让 git 顺序
  看得出来。
- **注释和 docstring 解释「为什么」，不解释「做了什么」。** 这个项目已经两次发出过
  「注释声称了一个代码没有的保护」——`sql_subject_store` 的抹除注释、`nginx.conf` 的

- **断言按 id 找行，不要按下标。** 多张表按 `created_at` 排序且没有 tiebreaker，
  同一瞬间写入的两行顺序是任意的。我今天就栽了：单跑绿、全量红。
- **响应模型按主体收窄**，不要一个模型加一堆 `if`。先例：`19b91e3`、`b97ddb3`、
  `a463b74`。
- 已发布 AgentVersion 的**内容哈希不得变化**。可选顶层文档不写就不带那个键，
  `end_user_access` 是第九个，有测试直接钉住。

## 5. 这个项目反复出现的那个 bug

**写进去了不等于有人够得着。** 这一轮至少抓到五次：

- `USER_CONFIRMATION` 全套建好，没有生产者；后来有了生产者，消费者拿不到 id
- 导出按钮不传 `agent_id`，服务端返回空
- `forgetAllSessionIds` 写好了，没有任何调用方
- `audit_events` 每层都在写，**一条读路径都没有**
- `failure_reason` 一直在 `RunResponse` 上，控制台从没渲染过

**每次都是后端测试全绿。** 判据不是「测试过了」，是「这条路走得通」——最好由一个
浏览器走一遍。写验收记录时这两句话要分开。

## 7. 合并前的硬门槛

**用户的原话：在合并或发布前必须重新取得 compose-e2e 绿色结果。**

CI 有四个 job：`backend-unit`、`backend-integration`、`web`、`compose-e2e`。
`compose-e2e` 会重建整个 compose 栈——**本地跑过的栈不算数**，它可能比代码旧。

注意：**开 PR 会触发第二次 CI**，PR 状态会显示 `UNSTABLE` 直到它跑完。等它，别看着
push 那次的绿就合。我在这个项目上犯过一次，当时 `backend-integration` 还在 pending。

而且 `success` 不等于跑过——`compose-e2e` 最早那次失败是**根本没走到项目测试**
（Ubuntu-Azure 镜像超时）。要确认它真的跑了：

```bash
gh run view <id> --log | grep "^compose-e2e" | grep -E "passed|✘"
```
